传输指南

无法直连 Last.fm 时提交播放记录

Cloud relay 是为无法直连 Last.fm API 的网络提供的可选备用通道。启用它不会取代正常的直接传输。

在 Chrome 应用商店中打开 隐私政策
本页内容 始终优先直接传输 启用备用通道 relay 接收哪些数据 批量传输和自动恢复 检查是否正常工作

始终优先直接传输

Use Cloud relay for scrobbles when direct delivery is unavailable 的含义就是如此：YM Bridge 首先从 Chrome 直连 Last.fm API。只有发生符合备用条件的直接网络错误后，relay 才会用于提交。

直连正常时，面板显示 Delivery target: direct to Last.fm，这些播放记录不会经过 relay。

启用备用通道

  1. 打开 Extension settings 并找到 Cloud relay。
  2. 启用 Use Cloud relay for scrobbles when direct delivery is unavailable。
  3. 首次使用时阅读数据说明并点击 Accept and keep relay fallback。在确认之前，备用传输不会开始。

您可以随时关闭此选项，只允许直接传输。

relay 接收哪些数据

仅在直接传输不可用时，已播放完成曲目的元数据和 Last.fm 会话密钥才会通过 HTTPS 发送到开发者运营的 Cloudflare Worker，并转发到 Last.fm。

relay 不会有意保存收听历史、会话密钥或请求正文。Cloudflare 作为基础设施提供商可能处理 IP 地址和技术请求元数据。完整说明请查看隐私政策。

批量传输和自动恢复

备用播放记录会进入队列，通常在累计 10 首曲目或 30 分钟后批量发送，以减少 Worker 流量。面板会把这些项目标记为 Relay 并显示在队列中。

YM Bridge 会定期检查 Last.fm 直连。连接恢复后，新的传输会自动回到直接通道，无需清除 relay 设置。

检查是否正常工作

  • 打开侧边栏并查看 Delivery target。
  • 打开 View queue 查看 Relay、Retry 或 Failed。
  • 如果批次超过预定时间仍未发送，请点击一次 Retry 并查看更新后的错误。
  • Last.fm 的 connected 仅确认已保存会话，并不能单独证明当前网络可以访问直接 API。
