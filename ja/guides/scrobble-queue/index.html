スクロブルキューを理解して再送する

キューは Last.fm への遅延を見える形にし、曲を黙って失わないようにします。状態を見ることで、再生中の曲と対応が必要な項目を区別できます。

Chrome ウェブストアで開く サポート
このページの内容 空のキューが正常な場合 キュー状態を読む 安全に再試行 配信経路を診断 古い曲情報や操作を修復

空のキューが正常な場合

現在の曲はリアルタイムで処理され、表示キューに残る必要はありません。そのため Queue is empty. Current playback is being handled live. は正常な状態です。

完了した配信はパネルの Last delivery と Last.fm の最近の曲で確認します。再生中の曲がすぐに完了済みスクロブルとして表示されるわけではありません。

キュー状態を読む

  • Pending: 条件を満たすか次の配信処理を待っています。
  • Relay: 直接配信が使えず、フォールバックのバッチを待っています。
  • Retry: 前回の試行に失敗し、拡張機能が次回を予定しています。
  • Failed: 手動再試行が必要、または Clear failed で削除できます。

安全に再試行

  1. View queue を開きます。
  2. Retry を一度押します。拡張機能は対象の配信を実行し、各状態を更新します。
  3. もう一度押す前に結果を待ちます。ネットワーク経路が使えないままなら、連続クリックでは直りません。
  4. Clear failed は失敗項目を破棄するときだけ使います。Last.fm の再接続は行いません。

配信経路を診断

パネル上部の Last.fm、Yandex Music、Scrobble queue を確認し、現在の曲の下にある Delivery target を読みます。

  • direct to Last.fm はブラウザの直接経路が有効です。
  • Cloud relay はフォールバックまたはバッチ処理中です。
  • connected は保存済み Last.fm セッションを示します。直接のプロフィールや統計リクエストはネットワークで遮断される場合があります。

古い曲情報や操作を修復

曲名、カバー、再生状態が Yandex Music と同期しない場合、問題は Last.fm より前にあります。Tools から Settings を開き、Control health を実行して Repair controls を使います。古い接続が残る場合は Yandex Music タブを再読み込みします。

問い合わせ時は Copy diagnostics を使い、共有したくない情報を削除してください。Last.fm のパスワードやセッションキーは絶対に公開しないでください。
