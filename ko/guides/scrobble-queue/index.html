스크로블 대기열 이해 및 재시도

대기열은 곡을 조용히 잃는 대신 지연된 Last.fm 전송을 보여 줍니다. 상태를 통해 현재 재생과 실제로 조치가 필요한 항목을 구분할 수 있습니다.

Chrome 웹 스토어에서 열기 지원
이 페이지의 내용 빈 대기열이 정상인 경우 대기열 상태 읽기 안전하게 재시도 전송 경로 진단 오래된 곡 정보 또는 컨트롤 복구

빈 대기열이 정상인 경우

현재 곡은 실시간으로 처리되므로 표시되는 대기열에 남아 있을 필요가 없습니다. 따라서 Queue is empty. Current playback is being handled live.는 정상 상태입니다.

완료된 전송은 패널의 Last delivery와 Last.fm 최근 곡에서 확인하세요. 재생 중인 곡이 즉시 완료된 스크로블로 나타나지는 않습니다.

대기열 상태 읽기

  • Pending: 곡이 조건을 충족하거나 다음 전송 주기를 기다립니다.
  • Relay: 직접 전송을 사용할 수 없어 대체 묶음을 기다립니다.
  • Retry: 이전 시도가 실패해 확장 프로그램이 다음 시도를 예약했습니다.
  • Failed: 수동 재시도가 필요하거나 Clear failed로 제거할 수 있습니다.

안전하게 재시도

  1. View queue를 여세요.
  2. Retry를 한 번 누르세요. 확장 프로그램이 가능한 전송을 실행하고 각 상태를 갱신합니다.
  3. 다시 누르기 전에 결과를 기다리세요. 네트워크 경로가 여전히 막혀 있다면 반복 클릭으로 해결되지 않습니다.
  4. Clear failed는 실패 항목을 버릴 때만 사용하세요. Last.fm을 다시 연결하지는 않습니다.

전송 경로 진단

패널 상단의 Last.fm, Yandex Music, Scrobble queue를 확인하고 현재 곡 아래의 Delivery target을 읽으세요.

  • direct to Last.fm은 브라우저의 직접 경로가 활성 상태임을 뜻합니다.
  • Cloud relay는 대체 전송 또는 일괄 처리가 활성 상태임을 뜻합니다.
  • connected는 저장된 Last.fm 세션을 확인합니다. 직접 프로필이나 통계 요청은 네트워크에서 여전히 차단될 수 있습니다.

오래된 곡 정보 또는 컨트롤 복구

곡명, 커버 또는 재생 상태가 Yandex Music을 더 이상 따라가지 않으면 문제는 Last.fm 이전 단계에 있습니다. Tools에서 Settings를 열고 Control health를 실행한 뒤 Repair controls를 사용하세요. 오래된 연결이 계속 보고되면 Yandex Music 탭을 새로고침하세요.

도움을 요청할 때 Copy diagnostics를 사용하고 공유하고 싶지 않은 정보를 지우세요. Last.fm 비밀번호나 세션 키를 절대 공개하지 마세요.
