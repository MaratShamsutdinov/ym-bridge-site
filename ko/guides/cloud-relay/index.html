전송 가이드

Last.fm 직접 연결이 불가능할 때 스크로블링

Cloud relay는 Last.fm API에 직접 연결할 수 없는 네트워크를 위한 선택적 대체 경로입니다. 이를 켜도 일반 직접 전송은 대체되지 않습니다.

Chrome 웹 스토어에서 열기 개인정보처리방침
이 페이지의 내용 직접 전송이 항상 우선 대체 경로 활성화 relay가 받는 데이터 일괄 처리 및 자동 복구 작동 확인

직접 전송이 항상 우선

Use Cloud relay for scrobbles when direct delivery is unavailable 설정은 이름 그대로 동작합니다. YM Bridge는 먼저 Chrome에서 Last.fm API로 직접 연결합니다. relay는 대체 가능한 직접 네트워크 오류가 발생한 뒤에만 사용됩니다.

직접 연결이 정상이면 패널에 Delivery target: direct to Last.fm이 표시되고 해당 스크로블에는 relay가 사용되지 않습니다.

대체 경로 활성화

  1. Extension settings를 열고 Cloud relay를 찾으세요.
  2. Use Cloud relay for scrobbles when direct delivery is unavailable를 켜세요.
  3. 처음 사용할 때 데이터 안내를 읽고 Accept and keep relay fallback을 누르세요. 동의하기 전에는 대체 전송이 시작되지 않습니다.

직접 전송만 요구하려면 언제든 옵션을 끌 수 있습니다.

relay가 받는 데이터

직접 전송을 사용할 수 없을 때만 완료된 곡의 메타데이터와 Last.fm 세션 키가 HTTPS로 개발자가 운영하는 Cloudflare Worker에 전송되고 Last.fm으로 전달됩니다.

relay는 청취 기록, 세션 키 또는 요청 본문을 의도적으로 보관하지 않습니다. 인프라 제공자인 Cloudflare는 IP 주소와 기술적 요청 메타데이터를 처리할 수 있습니다. 자세한 내용은 개인정보처리방침에 있습니다.

일괄 처리 및 자동 복구

대체 스크로블은 대기열에 들어가며 일반적으로 10곡 또는 30분 후 한 번에 전송됩니다. Worker 트래픽을 줄이기 위한 방식입니다. 패널은 항목을 Relay로 표시하고 대기열에 보여 줍니다.

YM Bridge는 Last.fm 직접 연결을 주기적으로 확인합니다. 연결이 복구되면 relay 설정을 지우지 않아도 새 전송이 자동으로 직접 경로로 돌아갑니다.

작동 확인

  • 사이드 패널을 열고 Delivery target을 확인하세요.
  • View queue에서 Relay, Retry 또는 Failed 상태를 확인하세요.
  • 예정 시간이 지나도 묶음이 남아 있으면 Retry를 한 번 누르고 갱신된 오류를 확인하세요.
  • Last.fm의 connected 표시는 저장된 세션을 확인할 뿐, 현재 네트워크에서 직접 API에 연결된다는 뜻은 아닙니다.
