無法直連 Last.fm 時提交播放記錄

Cloud relay 是為無法直接連接 Last.fm API 的網路提供的可選備援。啟用後不會取代正常的直接傳送。

在 Chrome 線上應用程式商店開啟 隱私權政策
本頁內容 一律優先直接傳送 啟用備援 relay 接收哪些資料 批次傳送和自動恢復 檢查是否正常運作

一律優先直接傳送

Use Cloud relay for scrobbles when direct delivery is unavailable 的含義正是如此：YM Bridge 先從 Chrome 直接連接 Last.fm API。只有發生符合備援條件的直接網路錯誤後，relay 才會用於提交。

直連正常時，面板顯示 Delivery target: direct to Last.fm，這些播放記錄不會經過 relay。

啟用備援

  1. 開啟 Extension settings 並找到 Cloud relay。
  2. 啟用 Use Cloud relay for scrobbles when direct delivery is unavailable。
  3. 首次使用時閱讀資料說明並按下 Accept and keep relay fallback。確認前，備援傳送不會開始。

您可以隨時關閉此選項，只允許直接傳送。

relay 接收哪些資料

僅在直接傳送無法使用時，已播放完成曲目的中繼資料和 Last.fm 工作階段金鑰才會透過 HTTPS 傳送至開發者營運的 Cloudflare Worker，並轉送至 Last.fm。

relay 不會刻意保留收聽記錄、工作階段金鑰或要求本文。Cloudflare 作為基礎設施供應商可能處理 IP 位址和技術要求中繼資料。完整說明請參閱隱私權政策。

批次傳送和自動恢復

備援播放記錄會進入佇列，通常在累積 10 首曲目或 30 分鐘後批次傳送，以減少 Worker 流量。面板會將項目標示為 Relay 並顯示在佇列中。

YM Bridge 會定期檢查 Last.fm 直連。連線恢復後，新的傳送會自動回到直接路徑，無需清除 relay 設定。

檢查是否正常運作

  • 開啟側邊欄並查看 Delivery target。
  • 開啟 View queue 查看 Relay、Retry 或 Failed。
  • 如果批次超過預定時間仍未傳送，請按一次 Retry 並查看更新後的錯誤。
  • Last.fm 的 connected 僅確認已儲存工作階段，無法單獨證明目前網路可連接直接 API。
